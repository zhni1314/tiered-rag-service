# 评测计划

> 状态：**未实现**。这份文档存在的原因是把「怎么证明它有效」写清楚，
> 比假装已经有指标更有用。这也是本项目当前最大的缺口。

## 要回答的三个问题

1. 混合检索比纯向量好多少？好在哪类查询上？
2. rerank 值不值得那一次 cross-encoder 前向？
3. 条件重写会不会漏掉该重写的轮次（见 D-003）？

## 指标定义

| 层 | 指标 | 定义 |
|---|---|---|
| 检索 | `recall@k` | 标注证据 chunk 出现在 top-k 的比例，k ∈ {1, 3, 5, 10, 20} |
| 检索 | `MRR` | 第一条正确证据的排名倒数均值 |
| 检索 | `nDCG@10` | 多级相关性打折累计增益 |
| 生成 | 忠实度 | 答案中每个 claim 能否被检索到的上下文支持（LLM-as-judge，需人工抽检 20% 校准） |
| 生成 | 越权命中 | `public` 档回答里出现 `secret` 档专有内容的次数 —— 必须为 0 |
| 生成 | 拒答正确率 | 库外问题正确返回「资料中未提及」的比例 |
| 工程 | P50 / P95 延迟 | 分「触发重写」「跳过重写」「缓存命中」三种情形统计 |
| 工程 | 每请求 LLM 调用数 | 验证 D-003 的成本论断是否成立 |

## 数据集构造

目标 **80–120 条**问答对，来自已入库 PDF，每条标注 `(question, gold_chunk_ids)`。

分层抽样，覆盖以下查询类型 —— 混合检索的收益差异主要体现在这里：

| 类型 | 例子 | 预期谁占优 |
|---|---|---|
| 关键词精确 | 「实验 7 的学时是多少」 | BM25 |
| 编号/缩写 | 「TCP 三次握手」「CVE-2021-xxxx」 | BM25 |
| 语义同义 | 「怎么防止被扫描」↔ 原文「端口扫描检测」 | 向量 |
| 跨段落综合 | 「整个课程考核怎么构成」 | 两者都不行，暴露 chunk 策略问题 |
| 库外问题 | 「食堂几点开门」 | 应拒答 |
| 多轮指代 | 先问 A，再问「A 和 B 有什么区别」 | 考验重写 |

标注用 `scripts/label_queries.py`（待写）：检索 top-20 → 人工勾选证据 chunk → 存 JSONL。

## 消融矩阵

固定生成模型和 Prompt，只换检索配置：

| 实验 | bm25_weight | vector_weight | rerank_top_n | 假设 |
|---|---|---|---|---|
| A 纯向量 | 0 | 1 | 3 | 基线 |
| B 纯 BM25 | 1 | 0 | 3 | 中文分词后可能已经不差 |
| C 当前配置 | 0.5 | 0.5 | 3 | 应优于 A、B |
| D 偏词法 | 0.7 | 0.3 | 3 | 关键词类查询占优时更好 |
| E 关掉重排 | 0.5 | 0.5 | 0 | 量化 rerank 的召回质量贡献 |
| F chunk 扫描 | — | — | — | 400 / 800 / 1200 三档 × overlap 0 / 20 / 100 |

另外单独测 D-003：构造 30 条**需要重写但不含表内代词**的追问，量漏重写率。

## 权限隔离验证

不需要标注，是一条硬性回归测试：

```
对每个 secret-only 问题 q：
  assert /chat(user_level="public", q) 的答案不含 secret 语料中的唯一标识串
  assert /chat(user_level="secret",   q) 命中正确
```

这条应该进 CI —— 它测的是边界，不是质量，所以不需要模型（可以 mock 检索层断言候选集）。

## 通过标准（我会怎么判断"这版可以了"）

- `recall@3` 混合检索 ≥ 纯向量 +10 个百分点，否则承认参数没调对或语料不合适
- 越权命中 = 0
- 忠实度 ≥ 90%，且人工抽检未发现「编造但流畅」的答案
- P95 延迟在跳过重写路径上 ≤ 触发重写路径的 60%，否则 D-003 的收益主张不成立
